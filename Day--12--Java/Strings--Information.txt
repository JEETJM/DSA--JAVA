1. First understand Java memory: Stack vs Heap

Java program memory mainly uses:

Stack Memory
Heap Memory

2. Stack Memory in Java

Stack memory is used for:

local variables
method calls
references
temporary data

Example:

public class Main {
    public static void main(String[] args) {
        int a = 10;

Stack
--------------------------------
main() method frame
--------------------------------

Here:

a is a primitive variable, so value 10 is directly stored in stack.

But:

String name = "Jeet";

name is not storing full "Jeet" inside stack.
It stores a reference/address of the actual String object.

3. Heap Memory in Java

Heap memory is used for:

objects
arrays
instance variables
String objects

Example:

String name = new String("Jeet");

Memory idea:

Stack
-------------------------
name = address 101
-------------------------


Heap
-------------------------
101 -> String object "Jeet"
-------------------------

So, object data is stored in heap, and stack keeps only the reference.

4. String Pool

String Pool is a special memory area inside heap.

It stores string literals to save memory.

Example:

String s1 = "Apple";
String s2 = "Apple";

Java does not create two separate "Apple" objects.

Memory:

Stack
-------------------------
s1 -> address 500
s2 -> address 500
-------------------------


Heap / String Pool
-------------------------
500 -> "Apple"
-------------------------

Both s1 and s2 point to the same "Apple" object.

That is why:

System.out.println(s1 == s2);

Output:

true

Because both references point to the same object.

5. What is String Interning?

String interning means storing only one copy of each unique string literal in the String Pool.

Example:

String a = "Mango";
String b = "Mango";
String c = "Mango";

Java creates only one "Mango" in String Pool.

String Pool
-------------------------
"Mango"
-------------------------

a, b, c all point to same Mango

This saves memory.

Very important concept.

Example 1: String literal
String s1 = "Apple";
String s2 = "Apple";

System.out.println(s1 == s2);

Output:

true

Because both use String Pool.

Example 2: Using new String()
String s1 = "Apple";
String s2 = new String("Apple");

System.out.println(s1 == s2);

Output:

false

Why?

Because:

String s1 = "Apple";

creates/uses object from String Pool.

String s2 = new String("Apple");

creates a new object in normal heap memory.

Memory:

Stack
-------------------------
s1 -> address 500
s2 -> address 900
-------------------------


Heap / String Pool
-------------------------
500 -> "Apple"
-------------------------


Normal Heap
-------------------------
900 -> "Apple"
-------------------------

Both values are same, but memory addresses are different.

So:

checks address, output is false.

9. Why Strings are Immutable in Java?

Immutable means:

Once created, a String object cannot be changed.

Example:

String s = "Hello";
s = s + " World";

Many students think "Hello" is changed into "Hello World".

But actually, Java creates a new String object.

Memory:

Before:
s -> "Hello"

After:
s -> "Hello World"

Old "Hello" still exists if referenced or waits for garbage collection.

So this:

s = s + " World";

does not modify old "Hello".

It creates a new object "Hello World" and makes s point to it.

10. Why did Java make String immutable?

There are several important reasons.

Reason 1: String Pool safety

String literals are shared.

Example:

String a = "Apple";
String b = "Apple";

Both point to the same object.

Now imagine if String was mutable:

a.change("Mango");

Then b would also become "Mango" because both point to same object.

That would be dangerous.

a -> "Apple"
b -> "Apple"

If a changes Apple to Mango:

a -> "Mango"
b -> "Mango"  ❌ problem

So Java made String immutable.

Reason 2: Security

Strings are used in important places like:

database username
password
file path
network URL
class loading
configuration

Example:

String url = "jdbc:mysql://localhost:3306/db";

If strings were mutable, someone could change the URL secretly.

That would be unsafe.

Reason 3: Hashcode caching

Strings are used as keys in HashMap.

Example:

HashMap<String, Integer> map = new HashMap<>();

map.put("Apple", 10);

HashMap uses the string hashcode to decide where to store data.

If String could change after insertion, the hashcode would change and HashMap would break.

Example problem if String was mutable:

put("Apple", 10)

Then Apple changes to Mango

Now HashMap cannot find the old key properly.

Because String is immutable, this problem does not happen.

Reason 4: Thread safety

Immutable objects are naturally thread-safe.

Multiple threads can use the same String without changing it.

Example:

String appName = "ExamPulse";

Many parts of a program can use this same string safely.

No one can modify the original object.

Reason 5: Better performance

Because Strings are immutable, Java can reuse them from String Pool.

This saves memory and improves performance.

            if (ch == 'a' || ch == 'e' || ch == 'i' || ch == 'o' || ch == 'u') {
                sb.deleteCharAt(i);
                i--;
            }
        }

        System.out.println("After removing vowels: " + sb);

        sc.close();
    }
}

Important:

i--;

Why?

Because after deleting one character, next character shifts left.

Example:

beautiful

If we delete one char, indexes change.

So we use i--.

23. Capitalize first letter of each word
import java.util.Scanner;

public class CapitalizeWords {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter sentence: ");
        StringBuilder sb = new StringBuilder(sc.nextLine().toLowerCase());

        boolean makeCapital = true;

        for (int i = 0; i < sb.length(); i++) {
            char ch = sb.charAt(i);

            if (ch == ' ') {
                makeCapital = true;
            } else if (makeCapital) {
                sb.setCharAt(i, Character.toUpperCase(ch));
                makeCapital = false;
            }
        }

        System.out.println("Capitalized sentence: " + sb);

        sc.close();
    }
}

hello jeet mondal

Output:

Hello Jeet Mondal
24. Why StringBuilder is faster?

Because StringBuilder modifies the same internal character array.

Conceptually:

StringBuilder object
--------------------------------
internal array: ['H', 'e', 'l', 'l', 'o', ...]
--------------------------------

When append happens:

sb.append(" World");

It adds characters into same internal storage.

But String creates new objects again and again.

25. Common mistakes
Mistake 1: Comparing StringBuilder using .equals()

Wrong:

StringBuilder a = new StringBuilder("Hi");
StringBuilder b = new StringBuilder("Hi");

System.out.println(a.equals(b));

Output:

false

Correct:

System.out.println(a.toString().equals(b.toString()));
Mistake 2: Index error
StringBuilder sb = new StringBuilder("Hello");

System.out.println(sb.charAt(5));

Wrong, because last index is 4.

H e l l o
0 1 2 3 4

Correct:

System.out.println(sb.charAt(4));
Mistake 3: Forgetting reverse changes original
StringBuilder sb = new StringBuilder("Java");
String rev = sb.reverse().toString();

System.out.println(sb);

Output:

avaJ

Original also reversed.

26. Best practice

Use StringBuilder when:

You are modifying string many times.
You are using loops with string concatenation.
You are creating large dynamic text.
You need reverse, insert, delete, replace operations.

Do not use it unnecessarily for simple fixed strings.

Example:

String name = "Jeet";

This is fine.

But for loop:

StringBuilder sb = new StringBuilder();

for (int i = 1; i <= 1000; i++) {
    sb.append(i);
}

This is better.

27. Interview short answer

StringBuilder is a mutable class in Java used to create and modify strings efficiently. Unlike String, it does not create a new object every time we change the text. It is faster than String for repeated modifications, but it is not thread-safe. Important methods are append(), insert(), delete(), replace(), reverse(), charAt(), setCharAt(), length(), capacity(), and toString().
